# DRG/DIP 3.0 离线分组查询与入组预演工具 · 最终需求分析与原型

**文档版本**：V3.0（最终版）
**技术栈**：Tauri v2 + Vue 3 + shadcn-vue + Tailwind CSS v4
**分组引擎**：JavaScript（运行于 Web Worker）
**数据源**：用户自行整理 Excel 导入（离线，数据不出院）


# 第一部分：需求分析

## 一、项目背景与目标

### 1.1 政策背景

按病组（DRG）和按病种分值（DIP）付费 3.0 版分组方案已于 2026 年 9 月正式发布。3.0 版 DRG 分组包括核心分组（ADRG）492 个病组、细分组（DRGs）825 个病组；3.0 版 DIP 核心病种库包括 5125 个病种，覆盖病例数从 2.0 版的 92% 提高到 95%。国家医保局要求实施按病种付费的地区和医疗机构在 **2026 年 12 月 31 日前**完成 3.0 版分组的切换准备工作，**2027 年 3 月底前**落地应用。

国家医保局已于 2026 年 9 月 9 日将 3.0 版分组方案的配置信息以 Excel 版面向社会公开，为本工具提供了权威的数据基础。同时，OpenDRG 等开源项目提供了 1.0/1.1/2.0 版的规则文件和分组器实现，为 3.0 版工具的快速开发提供了技术参考。

### 1.2 工具定位

面向医院医保办、病案室及临床科室的**离线桌面应用**，核心目标：

- **离线可用**：不依赖网络，数据不出院，满足医疗机构信息安全要求；
- **双引擎驱动**：同时支持 CHS-DRG 3.0 和 DIP 3.0 两套分组逻辑；
- **入组预演**：在病案首页提交前模拟官方分组结果，辅助主诊断和主手术操作优化；
- **跨版本对比**：支持 DRG 1.1/2.0/3.0 分组结果对比，直观展示规则变化影响；
- **用户自助**：用户从 HIS/病案系统导出数据，按模板整理 Excel 后导入，无需接口对接。

### 1.3 技术选型

| 层次 | 技术 | 说明 |
|---|---|---|
| 桌面框架 | **Tauri v2** | 安装包体积小（≤15MB），启动快，内存占用低 |
| 前端框架 | **Vue 3 + TypeScript + Vite** | 类型安全，开发效率高 |
| UI 组件 | **shadcn-vue + Tailwind CSS v4** | 基于 Reka UI，Data Table、Command、Card 等开箱即用 |

## 二、用户需求分析

### 2.1 目标用户角色

| 角色 | 核心诉求 | 使用场景 |
|---|---|---|
| **病案编码员** | 验证编码组合的入组结果，发现编码质量问题 | 病案首页编码完成后，批量运行预分组 |
| **医保办管理人员** | 评估科室 DRG/DIP 盈亏，分析高倍率/低倍率病例 | 月度结算前批量预演全院病例 |
| **临床医师** | 快速预判主诊断+主手术操作组合的入组结果 | 诊疗过程中辅助诊断选择 |
| **信息科技术人员** | 将分组能力嵌入现有系统 | 通过本地 API/CLI 调用 |

### 2.2 核心使用场景

**场景一：单病例快速查询。** 编码员输入主要诊断、主要手术操作及次要诊断/操作，工具立即返回 MDC→ADRG→DRG 三级分组结果，并展示入组路径和 CC/MCC 触发明细。

**场景二：批量病案预演。** 医保办从 HIS/病案系统导出病案首页数据，按工具提供的模板整理成 Excel，一次性导入完成全院或指定科室的预分组，输出入组率、未入组病例清单、高低倍率预警等统计报告。

**场景三：3.0 版规则变化对比。** 将同一病例数据分别在 2.0 版和 3.0 版规则下运行，对比分组结果差异，帮助编码人员快速识别规则调整带来的影响。

**场景四：本地化规则验证。** 针对所在统筹区的本地细分组规则，在工具中导入地方版规则文件，验证本地规则与国家版规则的差异。

| M3 | 单病例查询与预演 | P0 | 交互式单病例分组 |

### 3.2 各模块详细需求

#### M1：DRG 分组引擎（JavaScript + Web Worker）

- **功能描述**：在 JS 侧实现 CHS-DRG 3.0 版的三级分组逻辑，参照 OpenDRG JS 版的"知识库+规则库"架构。
- **输入**：主要诊断编码、主要手术操作编码、其他诊断编码列表、其他手术操作编码列表、性别、年龄、新生儿体重、离院方式。
- **输出**：MDC 代码、ADRG 代码、DRG 代码、入组路径、CC/MCC 触发明细、参考权重。
- **关键要求**：
  - 规则文件（`1_MDC.txt`、`2_ADRG.txt`、`3_DRG.txt`、`4_ADRG_DETAIL.txt`、`5_MCC.txt`、`6_CC.txt`、`7_CC.txt`）在应用启动时解析为 JS `Map` 索引。
  - 严格遵循 3.0 版"核心手术操作优先入组"的外科病例分组逻辑。
  - 正确加载并应用 3.0 版 CC/MCC 清单（MCC 压缩至约 1512 条），不沿用 2.0 版清单。
  - 支持重症先期分组规则，有创呼吸机 ≥96 小时需结合主要手术和核心治疗综合判定，区分伴 CRRT 与不伴 CRRT 两个细分组。
  - 支持机器人辅助手术的 9 个专属 DRG 细分组识别。
- **运行环境**：单病例在主线程直接调用（<5ms）；批量分组通过 **Web Worker** 执行，避免主线程阻塞。

#### M2：DIP 分组引擎（JavaScript + Web Worker）

- **功能描述**：实现 DIP 3.0 版的核心病种分组逻辑。OpenDRG 主要面向 CHS-DRG，DIP 需自行实现。
- **输入**：主要诊断编码、主要手术操作编码、辅助目录信息（年龄、离院方式等）。
- **输出**：DIP 病种代码、病种名称、分值、入组路径。
- **关键要求**：
  - 基于 5125 个核心病种库匹配（"主要诊断 + 主要手术操作"组合）。
  - 支持辅助目录修正规则（年龄、离院方式对分值的调整）。
  - 支持 DRG 基层病组 31 个和 DIP 基层病种 127 个的识别与标注。

#### M3：单病例查询与预演

- **前端界面**：
  - 诊断/手术编码输入框使用 **Command + Combobox** 实现模糊搜索（输入中文名称或部分编码联想）。
  - 主诊断/主手术支持拖拽排序。
  - 结果面板使用 **Card** 展示 MDC→ADRG→DRG 三级路径，CC/MCC 触发项用 **Badge** 高亮。
  - 规则追溯面板使用 **Collapsible** 展示命中的每条分组规则。
  - 提供"载入示例"按钮，快速填充演示数据。

#### M4：批量 Excel 导入与预演（核心模块）

**4.1 标准 Excel 模板**

| 列名 | 是否必填 | 说明 | 示例 |
|---|---|---|---|
| 病例号 | 必填 | 唯一标识 | ZY2026001842 |
| 主要诊断编码 | 必填 | ICD-10 编码 | I21.0 |
| 主要诊断名称 | 选填 | 便于核对 | 急性前壁心肌梗死 |
| 其他诊断编码 | 选填 | 多个用英文逗号分隔 | E11.9,N18.3,I10 |
| 主要手术操作编码 | 条件必填 | 有手术则必填 | 36.07 |
| 主要手术操作名称 | 选填 | 便于核对 | 冠状动脉药物洗脱支架植入术 |
| 其他手术操作编码 | 选填 | 多个用逗号分隔 | 88.72 |
| 性别 | 必填 | 男/女 | 男 |
| 年龄 | 必填 | 数字 | 67 |
| 离院方式 | 必填 | 医嘱离院/医嘱转院/死亡/其他 | 医嘱离院 |
| 住院总费用 | 选填 | 用于盈亏分析 | 52300.00 |
| 住院天数 | 选填 | 用于效率分析 | 8 |
| 新生儿体重 | 条件必填 | 新生儿病例必填 | 3200 |

**模板提供方式**：工具内提供"下载导入模板"按钮，生成带表头、示例数据和填写说明的 `.xlsx` 文件。

**4.2 导入流程（四步向导）**

1. **上传文件**：拖拽或选择 `.xlsx`/`.xls`/`.csv`，支持一次上传多个文件。
2. **字段映射**：自动识别表头；若用户列名不同，提供下拉框手动映射；必填字段未映射则标红。
3. **数据校验与预览**：逐行校验必填缺失、编码格式、枚举值；错误行高亮并给出原因；预览前10行。
4. **批量分组与结果展示**：进度条显示处理进度；完成后跳转结果页，用 Data Table 展示。

**4.3 数据校验规则**

- **基础校验**：必填非空、年龄为数字、性别/离院方式在枚举范围内、编码格式符合 ICD-10 / ICD-9-CM-3。
- **业务校验**：主要诊断是否在 MDC 清单中、主要手术是否在 ADRG 规则中、其他诊断是否在 CC/MCC 或排除清单中、新生儿病例是否填写体重。
- **分组后校验**：未入组病例单独列出，给出可能原因。

#### M5：跨版本分组对比

- **前端界面**：使用 **Tabs** 并排展示 1.1/2.0/3.0 三个版本的结果，版本间差异用 **Badge** 高亮。
- **后端逻辑**：SQLite 中存储多版本规则数据；同一病例并行调用三个版本的分组函数；输出差异分析。

#### M6：规则库管理

- **前端界面**：规则版本列表使用 **Data Table**；导入使用 **Dialog + File Upload**。
- **核心能力**：
  - 规则文件导入：解析官方 Excel 配置信息，转换为 OpenDRG 规则格式。
  - 规则版本管理：SQLite 中建立 `rule_versions` 表，支持多版本并存和切换。
  - 本地化规则覆盖：支持导入地方版细分组调整文件。
  - 规则校验：导入时校验完整性，检测冲突条目。

#### M7：结果导出与报表

- **导出格式**：Excel、CSV、PDF。
- **报表类型**：单病例分组报告（含路径和规则追溯）、批量预演统计报告、跨版本对比报告。

#### M8：API/CLI 集成接口

- **本地 HTTP API**：可选，供 HIS/EMR 调用。
- **CLI**：支持 `group --input xxx.csv --output result.csv` 批量处理。


## 四、数据需求

### 4.1 基础规则数据

| 数据项 | 来源 | 说明 |
|---|---|---|
| MDC 清单（26 个） | 国家医保局官方 Excel / OpenDRG 规则库 | 主要诊断大类定义 |
| ADRG 清单（492 组） | 国家医保局官方 Excel / OpenDRG 规则库 | 核心疾病诊断相关组 |
| DRG 细分组清单（825 组） | 国家医保局官方 Excel / OpenDRG 规则库 | 最终分组定义 |
| ADRG 详细规则 | 国家医保局官方 Excel / OpenDRG 规则库 | 每个 ADRG 的诊断/手术匹配条件 |
| MCC 清单（约 1512 条） | 国家医保局官方 Excel | 严重并发症/合并症 |
| CC 清单 | 国家医保局官方 Excel | 一般并发症/合并症 |
| CC/MCC 排除列表 | 国家医保局官方 Excel | 不参与分层的诊断 |
| DIP 核心病种库（5125 个） | 国家医保局官方 Excel | 诊断+手术操作组合 |
| 基层病种清单 | 国家医保局官方文件 | DRG 31 组、DIP 127 种 |

### 4.2 数据存储方案

1. **内嵌规则文件**：OpenDRG 规则文件随应用打包到 Tauri 的 `resources` 目录。
2. **SQLite 索引层**：存储规则版本元数据、编码索引、用户配置。
3. **内存索引**：JS 侧启动时将规则文件解析为 `Map<String, Vec<Rule>>`，确保毫秒级响应。

### 4.3 用户输入数据

用户从 HIS/病案系统导出数据，按工具提供的 Excel 模板整理后导入。工具不直接对接任何接口，数据完全由用户掌控。

## 六、3.0 版关键适配点

### 6.1 CC/MCC 清单大幅精简

2.0 版 MCC 清单 4477 条、CC 清单 8008 条；3.0 版 MCC 压缩至约 1512 条。分组引擎需使用 3.0 版清单重新构建。工具应内置 CC/MCC 清单对比功能。

### 6.2 外科分组逻辑切换为"术式优先"

3.0 版将外科病例分组从"以主要诊断为核心"改为"以核心手术操作为优先"。分组引擎中 ADRG 的匹配逻辑需相应调整，手术操作的匹配优先级需高于诊断匹配。

### 6.3 重症先期分组规则修改

有创呼吸机 ≥96 小时不再无条件触发先期分组，需结合主要手术和核心治疗综合判定，区分伴 CRRT 和不伴 CRRT 两个细分组。

### 6.4 基层病种识别

3.0 版首次设置 DRG 基层病组 31 个、DIP 基层病种 127 个。工具需在分组结果中标注病例是否落入基层病种范围。

## 原型说明

### 四个核心视图

1. **单病例查询**：左侧输入主要诊断、主手术操作、其他诊断和患者信息，右侧实时展示 MDC→ADRG→DRG 三级分组路径、权重费用参考、CC/MCC 触发明细和规则追溯面板。输入框支持编码联想，载入示例按钮可快速填充演示数据。

2. **批量预演**：顶部是 Excel/CSV 拖拽导入区和"下载导入模板"按钮；中部是统计卡片（总病例数、入组率、未入组、预警）；下部是 Data Table 展示逐病例分组结果，未入组行以浅红底色标识。

3. **版本对比**：顶部展示病例基本信息；中部三列并排展示 1.1、2.0、3.0 三个版本的分组结果，3.0 列以高亮边框突出；底部是差异分析，用图标标注一致项和需关注项。

4. **规则管理**：以卡片形式展示已加载的规则库版本（3.0 当前使用、2.0 用于对比、DIP 3.0），显示各版本的 ADRG/DRG/MCC 数量与加载状态；右下角预留"导入本地化规则"入口。

### 下一步建议

1. **细化 Excel 模板**：基于原型中的字段设计，产出实际的 `.xlsx` 模板文件和填写说明。
2. **补充导入向导原型**：当前原型展示了导入区，但四步向导（上传→映射→校验→分组）可进一步细化。
3. **补充移动端适配**：如果需要支持平板或手机查看，可增加响应式布局。
4. **对接真实规则数据**：将 OpenDRG 的 1.1/2.0 规则文件和 3.0 版官方 Excel 转换为 JS 可解析格式，接入原型进行真实分组测试。
